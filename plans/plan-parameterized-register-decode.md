# Parameterized Register Decode Block

A focused plan to make the synthesized register-handler module (e.g.
`ipRegs`) variant-correct, so stage C3 of
`plan-param-constant-collision.md` (move parameterizable types/structs out
of the package into owning modules) can land without breaking the register
handler. The SV shape is validated by a hand-written proto before the
generator (`moduleRegs.py`) is changed, because the generated decode needs
review.

Status: **historical / implemented in working tree.** This design became
**C3.R** in `plan-param-constant-collision.md`; current status and
verification details are recorded there in the C3.R progress row. This
file remains the design/proto history for that work and should not be
treated as the active execution owner.

## Why this is needed

- C3 removes block-param-backed parameterizable constants and the
  parameter-dependent types/structs from the package; they become
  module-local in the owning parameterized module.
- `ipRegs` is an **auto-synthesized** register-handler block. It is flagged
  `isParameterizable = 1` (because the parent `ip`'s registers/memories
  reference parameterizable structs) but carries **no own `params:`**, so
  `blockParameterizedDecls` selects nothing for it and it gets no module
  parameters. Its body (generated by `moduleRegs.py`) declares
  `ipCfgSt`/`ipDataSt`/`ipMemSt`/`ipMemAddrSt` directly. Once those types
  leave the package, `ipRegs.sv` no longer compiles.
- Decision (user, 2026-06-05): **parameterize the register handler** rather
  than pin it to worst-case. The handler inherits the parent's params, `ip`
  forwards its variant values, and the data-field decode becomes
  parameter-relative. The **address map stays on worst-case (max) sizes** —
  already handled by `calcAddresses`; this plan does not touch it.

## The hard part the design must solve

`moduleRegs.py` splits each register into 32-bit APB words
(`segment_register_gen`) and emits one flop + decode block per word. Both
the per-word bit slices **and the number of words** are derived at
generation time from the struct width resolved at the constant's default
(= worst-case). For parameterized registers the word count varies per
variant, and `ipRegs.sv` is generated once but instantiated at multiple
variants:

| register | struct | variant0 (`IP_DATA_WIDTH=8`) | variant1 (`=70`) |
|---|---|---|---|
| `ipCfg` (rw) | `enable(1)+mode(2)+threshold(IP_DATA_WIDTH)` | 11 bits → 1 word | 73 bits → 3 words |
| `ipLastData` (ro) | `marker(1)+data(IP_DATA_WIDTH)` | 9 bits → 1 word | 71 bits → 3 words |
| `ipMem` (memory) | `data(IP_DATA_WIDTH)` | 8 bits → 1 word | 70 bits → 3 words |

So it is not only the slice literals (e.g. `[72:64]`) that parameterize —
the count of `DFFREN`/case-word blocks does too. A single module must cover
both, while the APB **address footprint** per register stays at the
worst-case word count (the address map is fixed).

## Design

Principle: register storage is the **parameterized struct** (variant
width); the APB address footprint per register stays **max** (worst-case
word count). Words that do not exist for a narrow variant have their data
flop/update elaborated away via SV `generate`, but their **addresses stay
decoded**: a write to unused address space within the register's worst-case
footprint is **silently ignored** (no `pslverr`, ACK only) and a read
returns 0. No new error cases are introduced — absent words must not fall
through to the global `default: pslverr` branch.

Per register, the generated `moduleRegs` output becomes:

- `<paramStruct> <reg>_reg;` — module-local parameterized struct (emitted
  from the block view's `parameterizedDecls`, same source C3.2 consumes).
- A width localparam, preferring `localparam int <REG>_W = $bits(<reg>_reg);`
  so the template does not re-derive field math (the struct already encodes
  it from the module parameters).
- The register's **whole worst-case footprint is decoded as one
  case-`inside` range** with an inner per-word `case` and an inner
  `default: ;` (the existing memory-register pattern at
  `section_02b_memregs`), so any address inside the register's max footprint
  is ACKed and unused words fall to the inner `default: ;` — never to the
  global `default: pslverr`. Regular `rw`/`ro` registers move to this
  range+inner-case shape (today they use one top-level case entry per word,
  whose absence would error).
- For each potential word `n` in `0 .. maxWords-1` (`maxWords` from the
  worst-case width, i.e. the existing segment count):
  - wrap the word's data flop and its data update in
    `generate if (<REG>_W > 32*n) ... end endgenerate` (the inner case entry
    that ACKs the address stays present regardless);
  - slice bounds: lower words use fixed 32-bit boundaries; the top present
    word uses `[<REG>_W-1 : 32*n]`;
  - `DFFREN`/`pwdata` width for the top word becomes `<REG>_W-32*n`.
- Address constants / SIZE / case-`inside` ranges remain computed on the
  worst-case width (unchanged), so `REG_*` localparams are byte-identical
  across variants and to the pre-change output.

Sub-decisions to settle during the proto (call out for the reviewer):

1. `$bits(reg)` vs an explicit param-derived width localparam. `$bits` is
   the simplest and avoids duplicating struct math; confirm Verilator
   elaborates `generate if ($bits(...) > k)` cleanly.
2. Absent high-address words for a narrow variant (decided): writes to
   unused address space are **silently ignored**, reads return 0, and **no
   error cases are added**. Achieved by decoding the whole register
   footprint as a range with an inner `default: ;` (above), so unused words
   never reach the global `default: pslverr`.
3. `regType` coverage: `rw`, `ro`, `memory`, and `ext` segmented paths all
   pass through the same generate guard. The proto must exercise `rw`,
   `ro`, and `memory` (the three shapes `ipRegs` uses).

## Proto first (validate the SV shape) — `proto/rtl`

The proto area at the repo root (`/work/ws/debayer/proto/rtl`) already
follows the pattern this needs: hand-written SV + Verilator testbenches as
numbered Makefile steps, with `tb_mparam`/`tb_dual_instance` building two
parameter instances in one compiled design. Add a new step here that proves
the generate-based variant-aware register decode is sound **before** the
generator is changed.

New files:

- `proto/rtl/interfaces/apb_if.sv`, `proto/rtl/interfaces/memory_if.sv` —
  minimal proto interfaces if not already present (mirror the project
  `apb_if`/`memory_if` surface used by `moduleRegs`).
- `proto/rtl/rtl/reg_decode_mparam.sv` — hand-written register-decode module
  in the **exact target generated shape**: inherits a `DATA_WIDTH`-style
  parameter, declares module-local parameterized `cfg`/`lastData`/`mem`
  structs, and emits `generate`-guarded variant-aware word decode with the
  address map fixed on the worst-case width. This is the artifact the
  reviewer signs off on; `moduleRegs.py` will be made to emit it.
- `proto/rtl/test/tb_reg_decode.sv` — instantiates `reg_decode_mparam` at
  **two widths in one build** (e.g. 8 and 70, mirroring `ipCfg`/`ipLastData`/
  `ipMem`). Drives APB writes/reads and a memory access; asserts the
  parameterized field round-trips correctly at each width; confirms no
  out-of-range part-selects and Verilator `-Wall` clean.

Makefile: add `step5` (parameterized register decode) and include it in
`all`.

Proto exit criteria:

- `make step5` passes; both width instances coexist in one compiled design.
- Narrow variant (1 word) and wide variant (3 words) both decode correctly.
- A write to the narrow variant's unused (absent-word) address space is
  silently ignored — no `pslverr` asserted — and a read of it returns 0.
- `-Wall` clean (no SELRANGE / WIDTH surprises in the generate-guarded
  paths).

## Generator change (only after proto sign-off) — `builder/base`

1. **Reg-handler inherits parent params.** In `projectCreate`, add a
   post-parse step that, for each `isRegHandler` block, inserts
   `blocksparams` rows mirroring the parent block's params (the parent is
   the container of the handler's single instance — same lookup
   `calcBlockConfigInfo` uses at `is_reg_handler`). This makes module
   parameters emit and lets `deriveParameterizedDeclSets` select the
   handler's module-local structs. **Task:** locate the reg-handler block
   synthesis pass (the one that also emits the leaf-to-handler
   `connectionMap`, referenced at `_registerBusInterfacePort`,
   `processYaml.py:2258`) and order this step after it but before
   `deriveParameterizedDeclSets()` / `calcBlockConfigInfo()` consumers.
2. **`ip` forwards params to `uIpRegs`.** In
   `moduleInterfacesInstances.py` instance emission, reg-handler instances
   pass `.PARAM(PARAM)` forwarding the parent module's own params (today the
   instance emission only forwards `variant_data` for sub-instances bound to
   a variant).
3. **`moduleRegs.py`** emits: the inherited module parameters, the
   module-local parameterized structs (from `parameterizedDecls`), and the
   `generate`-guarded variant-aware word decode with `$bits`-based bounds —
   matching the signed-off proto shape. Address constants/map stay
   worst-case.

## Validation

- Proto `make step5` passes (above).
- `examples/ip_test`: `make clean && make db && make gen`. Inspect:
  - `ipRegs.sv` — inherited params, module-local parameterized structs,
    `generate`-guarded decode; `REG_*` address constants unchanged.
  - `ip.sv` — field-wise widening at the `ipDataIf` input removed (item 4
    of the C3 plan), because `ipDataSt` is now variant-width end to end.
  - `ip_package.sv` — no block-param-backed parameterizable constants or
    their parameter-dependent types/structs (eval-derived `IP_DATA_WIDTH_X2`
    stays).
- `make run` — SystemC model prints `No error`.
- `make run-vl` — `uSrc` + `uIp0` (variant0, width 8) tandem passes;
  additionally confirm the `uIp1` (variant1, width 70) instantiation
  elaborates and the 3-word decode path is exercised.
- Diff the `REG_*` address constants against the pre-change baseline to
  prove the address map did not move.

## Explicitly out of scope (separate plans)

- **`ip_top` matched-connection payload naming.** `ip_top` (non-parameterized
  container) names `srcOut0St`/`srcOut1St`, which are `isParameterizable` and
  leave `src_package` under C3.1; `ip_top` cannot reach `src`'s module-local
  typedef. This is the Q9 / C3.5 cross-variant boundary (the SystemC analog
  is the `push_ack_port_thunker` at `ip_top`). Distinct from the register
  handler; needs its own plan.
- **Eval-derived constant emission (C4).** `IP_DATA_WIDTH_X2` and the
  `evalCoupled` path remain deferred (see
  `project_parameterized_eval_deferred`).
