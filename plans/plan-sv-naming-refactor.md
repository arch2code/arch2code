  hard damage before anything else. It never deletes, overwrites or moves
  onto a file that is any artifact's current path. When it is unsure it
  leaves the file and reports a TODO that says what to do, and a conflict it
  cannot resolve halts the chain before any damage. One general guard covers
  each class of case; there is no ownership inference. `make migrate` never

## Where names come from today

- A generated SV file is named after the bare block or include name:
  `isp_gain/rtl/gain.sv`, `rtl/gain_package.sv`.
- The module and package inside it are project-qualified by
  `qualifyModuleIdentity` (pysrc/processYaml.py). `gain.sv` declares
  `isp_gain_gain`, and `gain_package.sv` declares `isp_gain_gain_package`.
- The prefix is skipped when a name already equals the project name or starts
  with `<project>_`. That is why `debayer/rtl/debayer.sv` declares `debayer`.
- `deriveModuleIdentities` persists two maps: `BLOCKMODULENAME` and
  `CONTEXTMODULEIDENTITY`. Both SV names and C++20 module and namespace names
  use them. So today one value names the SV module and the C++ module.
- The composed root isp_top holds several block names that more than one IP
  defines: `apb_decode` and `cpu` (10 copies each), `rgb_video_src`,
  `rgb_video_sink`, `raw_video_src` and `raw_video_sink` (4 to 6 each). The
  project prefix is the only thing keeping them apart.

The ISP rename does not depend on item 11. Once a block is named
`isp_gain_calculation` inside project `isp_gain`, the prefix is skipped, so
the module is already `isp_gain_calculation`. The same holds for packages. The
two parts can land in either order.

## Part A: item 11 in builder/base

### Rules

- Three optional top-level project keys: `svFilePrefix`, `scFilePrefix` and
  `fwFilePrefix`. Omitting a key and setting `""` mean the same thing.
- An SV artifact's filename is `<svFilePrefix><name><fileMap suffix>`, and the
  module or package it declares is that filename stem. This covers:
  - block modules
  - register handlers (`_regs`)
  - routers
  - context packages and tb packages
  - verilated wrapper bodies and tops
- `qualifyModuleIdentity` no longer applies to SV names.
- `scFilePrefix` and `fwFilePrefix` rename files only. C++ class names, C++20
  module names and namespaces keep today's project qualification.
- Each project's own prefix applies to its artifacts, so an IP spells the same
  names standalone and inside a composing root.

### Changes

- **projectCreate.** Read the three keys and persist an SV module-name map per
  block and a package name per context. `BLOCKMODULENAME` and
  `CONTEXTMODULEIDENTITY` stay as the C++ identities. The SV templates switch
  to the new maps: module declaration, endmodule label, instantiation, package
  declaration and import, wrapper DUT instantiation, and apbDecode and regs
  modules.
- **Filenames.** `expandNewModulePath` and the artifact rows apply each
  language's prefix to the stem, and the build manifest, rtl.f, the VL tops and
  `A2C_VL_TOP_<block>` follow from those rows. Verilated `V<top>` class names
  follow the new top names.
- **Collision check.** Keep the existing check on every block, keyed on the
  SV name, and report both blocks with their owning projects.
- **Scaffold.** `pysrc/newProject.py` writes the three keys as commented lines
  with a short description of each.
- **Migration.** When a prefix changes, `make migrate` moves each existing
  generated implementation file (rtl/*.sv, model/*.cppm, fw) to its new name
  byte for byte. It then relabels user `endmodule:` labels, which
  `migrateModuleEndlabel.py` already does for the qualified name.
- **Tests.**
  - Omitted and `""` give identical output.
  - Each language's prefix works on its own.
  - Every emitted SV design unit's name equals its file stem.
  - Two IPs with different prefixes compose correctly.
  - A collision produces a clear diagnostic.
  - `make migrate` keeps user regions across a prefix change.
- **Examples.** Every base and pro example whose block names do not start with
  the project name gets new module names. pipeline-test regenerates them, and
  those files go into the base commit.

### Proof

- A script walks every generated and user `.sv` file in a project and checks
  that each module and package name equals its file stem. It runs on the base
  and pro examples and, in Part B, on every ISP repo.
- `make clean`, the unit suite and pipeline-test, as usual.

### What moves in each IP

Every step uses `git mv`, so git records the files as renamed and keeps their
history.

- **YAML.** `yaml/<ip>.yaml` and `yaml/<ip>_tb.yaml`; block keys, instance
  types, connections, variants and `include:` lists; `prj/yaml` project files.
- **Implementation files.** `rtl/<blk>.sv`, `model/<blk>.cppm`,
  `tb/<blk>/` and the `<blk>Config.cpp` / `Testbench.cppm` / `External.cppm`
  files inside it, `verif/` wrappers and `fw/` headers. These are moved first,
  then regenerated with `make clean`, `make db` and `make gen`.
- **User code.** C++ class and module names in user regions, `createInstance`
  strings, and user-written `endmodule:` labels.
- **Build files.** `include/make/shared.mk` (`HDL_TOP_MODULE`),
  `rundir/regr_<ip>.json` and `rundir/default.json` (block and config names),
  and the README.
- **Test paths.** Regression test paths such as
  `/model_tests/basic/gain/...` take the new block name. The known baselines
  (isp_ccm 22/30, isp_awb 28/30) keep their counts under the new paths.

- `prj/yaml/isp_topProject.yaml`, `yaml/isp_top_tb.yaml` tb blocks, root

## Follow-ups

- **Explicit file type in the fileMap (user, 2026-09-24).** Each fileMap
  entry gets a `fileType` key with the value `sv`, `sc` or `fw`, and
  `artifactPaths.fileNamePrefix` picks the prefix from it. This replaces the
  Part A inference from ext values and `basePath: fwInc`, which breaks
  quietly when someone adds an entry that fits neither pattern.
  - projectCreate rejects an entry that has no `fileType` or has an unknown
    value. This covers the entries in `config/project.yaml` and any entries a
    user project adds.
  - The entries in `config/project.yaml` and every example project's fileMap
    get the key. `make migrate` adds it to user project files that override or
    extend the fileMap.
  - Project-mode entries still take no prefix, whatever their `fileType`.
  - The code already uses "fileType" for fileMap entry names and ext keys.
    Check that the new key does not clash with that use, and pick another name
    if it does.
  - Proof: the unit suite, pipeline-test and the name check stay green with
    output byte-identical to Part A.

## Risks

- Regression test paths change, so any saved list of failing run names
  (memories, docs) needs updating alongside the baselines.
- Anything outside these repos that instantiates an IP module by its old
  name, such as a customer netlist or a CI artifact name, breaks. None is
  known in this workspace.
- The move touches a lot of files at once. One commit per IP keeps each
  review small. Moving files with `git mv` before regenerating keeps git's
  rename detection working.
